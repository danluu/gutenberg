## How to run confirmation

Start with the smoke commands and full/sharded commands in `RUN_ON_ANOTHER_MACHINE.md`. For issue-report work, use `likely-real-issues.jsonl` or the table below as the queue.

Useful commands:

```bash
jq -r 'select(.runnable) | [.index,.transport,.canonicalSignature,.bugType,.canonicalSpec] | @tsv' fuzz-handoff/distinct-manifest-20260505/likely-real-issues.jsonl
jq -r 'select(.runnable|not) | [.index,.transport,.canonicalSignature,.bugType,.canonicalStatusPath] | @tsv' fuzz-handoff/distinct-manifest-20260505/likely-real-issues.jsonl
```

Confirmation result handling:

- If the canonical repro fails in a product-looking way on the refreshed base, inspect its Playwright trace/log and draft an issue report for that `bugType`.
- If the canonical repro passes, do not immediately close the bug; inspect whether the spec was written to fail on reproduction or only record state. Then compare with the source STATUS path and decide whether it is fixed, unstable, or needs a better repro.
- If no canonical spec exists, reconstruct a realistic repro from the listed STATUS/summary/signatures before filing.
- Consolidate multiple rows only when the refreshed-base confirmation shows the same root cause and user-visible symptom.
